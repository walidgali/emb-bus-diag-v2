# أداة تشخيص نواقل الأنظمة المدمجة

> وصف المشروع ودليل الاستخدام من الصفر

# 1. ما هو المشروع؟

emb-bus-diag-v2 أداة سطر أوامر مكتوبة بلغة C11 لتشخيص الحساسات والأجهزة المتصلة بالأنظمة المدمجة (مثل Raspberry Pi ولوحات Linux المدمجة) عبر عدة نواقل اتصال.

تقرأ الأداة قيمة من الجهاز مراراً، وتحوّلها إلى قيمة فيزيائية (فولت أو درجة حرارة)، وتحكم على حالتها (سليمة / تحذير / حرجة / خطأ)، وتحسب إحصاءات لحظية تكشف القيم الشاذة واتجاه التغيّر، ثم تحفظ النتيجة في تقرير JSON.

يمكن استخدامها لفحص لوحة جديدة، أو مراقبة جهد بطارية، أو اكتشاف حساس يعطي قراءات غير مستقرة، أو دمجها في سكربتات الأتمتة بفضل رموز الخروج الواضحة.

## أبرز المميزات

- **خمس واجهات:** I2C وSPI وCAN وUART وModbus TCP، بالإضافة إلى وضع تجريبي (Mock) يعمل بدون أي عتاد.

- **ملفات تعريف للحساسات:** INA219 (جهد) وADS1115 (جهد بإشارة) وTMP102 (حرارة بإشارة)، أو raw مع تحديد المقياس ونوع القياس يدوياً.

- **إحصاءات لحظية:** المتوسط، المتوسط المتحرك الأسّي (EMA)، التباين، درجة Z لكشف القيم الشاذة، الميل (الاتجاه)، والمدى.

- **تقرير JSON** بآخر قراءة والإحصاءات.

- **مكتبة مشتركة** libembdiag.so للتحكم بمحرك الإحصاءات من Python.

- **اختبارات آلية** (C وPython وCLI) وفحص على GitHub عند كل رفع، مع فحص الذاكرة بأدوات ASan وUBSan.

# 3. المتطلبات

- نظام Linux (Raspberry Pi OS أو Ubuntu أو Debian). الأداة تستخدم ترويسات نواة Linux، لذلك لا تُبنى على Windows أو macOS مباشرة؛ ويمكن تجربة الوضع التجريبي على WSL2.

- gcc وmake وgit وpkg-config، وpython3 (للاختبارات ومكتبة Python).

- libmodbus-dev اختيارية: تلزم فقط لدعم Modbus. إن لم تكن مثبّتة فتُبنى الأداة بدونه.

# 4. الاستخدام من الصفر خطوة بخطوة

## الخطوة 1: تثبيت الأدوات

```bash
sudo apt update
sudo apt install -y build-essential git pkg-config python3
sudo apt install -y libmodbus-dev # اختياري: لدعم Modbus
```

## الخطوة 2: تنزيل المشروع

```bash
git clone https://github.com/walidgali/emb-bus-diag-v2.git
cd emb-bus-diag-v2
```

## الخطوة 3: البناء

```bash
make
ls -l emb-bus-diag-v2
```

يتحقق make تلقائياً من وجود libmodbus. لفرض البناء بدونها: make WITH_MODBUS=0، ولفرضها: make WITH_MODBUS=1.

## الخطوة 4: أول تشغيل (بدون عتاد)

```bash
./emb-bus-diag-v2 --bus mock -n 4 -i 100
```

يظهر خرج مشابه لما يلي (القيم عشوائية في الوضع التجريبي):

```bash
[1/4] Val=6.2880 V | OK | EMA=6.2880 | Z=0.00 | Trend=0.0000 | Range=0.0000
[2/4] Val=6.1240 V | OK | EMA=6.2552 | Z=0.00 | Trend=-0.1640 | Range=0.1640
[3/4] Val=6.2520 V | OK | EMA=6.2546 | Z=0.00 | Trend=-0.0180 | Range=0.1640
[4/4] Val=6.2200 V | OK | EMA=6.2476 | Z=0.00 | Trend=-0.0076 | Range=0.1640
Report saved to report.json
```

## الخطوة 5: قراءة الخرج

| **الحقل** | **المعنى**                                                                                                                                   |
|----------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Val                              | القيمة بعد تطبيق المقياس ووحدتها (V أو C أو hPa)                                                                                             |
| OK / WARNING / CRITICAL / ERROR  | حالة القراءة بحسب العتبات المدمجة                                                                                                            |
| EMA                              | متوسط متحرك أسّي (معامل 0.2) يخفف الضجيج                                                                                                      |
| Z                                | انحراف القراءة عن العينات السابقة بوحدات الانحراف المعياري. لا تظهر قبل توفر 4 عينات سابقة، وتظهر كلمة OUTLIER عندما تتجاوز القيمة المطلقة 3 |
| Trend                            | ميل خط الاتجاه لكل عينة (موجب = ارتفاع)                                                                                                      |
| Range                            | الفرق بين أكبر قيمة وأصغرها                                                                                                                  |

العتبات المدمجة: الجهد بين 3.3 و14.2 فولت سليم، وخارج 3.0 إلى 14.8 فولت حرج. الحرارة بين 5 و60 درجة سليمة، وخارج 0 إلى 75 حرجة، وخارج 40- إلى 125 خطأ. الضغط بين 950 و1050 hPa سليم.

## الخطوة 8: القراءة من جهاز حقيقي

جرّب دائماً الوضع التجريبي أولاً للتأكد من سلامة الأداة، ثم انتقل إلى العتاد. التفاصيل الكاملة في الملف docs/HARDWARE.md.

**I2C** (حساس جهد INA219 وحساس حرارة TMP102): فعّل الناقل من sudo raspi-config ثم Interface Options ثم I2C، ووصّل SDA وSCL وGND وجهد 3.3 فولت، ثم اكتشف العنوان:

```bash
sudo apt install -y i2c-tools
i2cdetect -y 1
# INA219: سجل الجهد 0x02، العنوان الافتراضي 0x40
./emb-bus-diag-v2 --bus i2c -b 1 -a 0x40 -r 0x02 --profile ina219 -n 10
# TMP102: سجل الحرارة 0x00، العنوان الافتراضي 0x48
./emb-bus-diag-v2 --bus i2c -b 1 -a 0x48 -r 0x00 --profile tmp102 -n 10
**تنبيه:** لا توصّل أبداً إشارات 5 فولت بلوحة Raspberry Pi. وإن ظهر رفض صلاحية فأضف مستخدمك لمجموعة i2c أو استخدم sudo.
```

**SPI:** العقدة /dev/spidev\<b\>.\<a\> حيث b رقم الناقل وa خط الاختيار (CS):

```bash
./emb-bus-diag-v2 --bus spi -b 0 -a 0 -r 0x01 --profile raw --metric voltage --scale 0.001
```

**CAN:** تنتظر الأداة (حتى ثانية) إطار بيانات معرّفه يساوي قيمة -a. للتجربة على واجهة افتراضية:

```bash
sudo modprobe vcan
sudo ip link add dev vcan0 type vcan && sudo ip link set up vcan0
./emb-bus-diag-v2 --bus can -b 0 -a 0x123 --profile ina219 -n 1 &
cansend vcan0 123#5DC0 # الحزمة can-utils
```

لواجهة حقيقية: export EMBDIAG_CAN_IFACE=can0 بعد تشغيلها بسرعة النقل المناسبة. المعرّفات المدعومة حتى 255.

**UART:** الإعدادات بمتغيرات البيئة. يرسل الوضع الافتراضي (poll) بايتاً واحداً هو رقم السجل ثم ينتظر ردّاً من بايتين (الأعلى أولاً) خلال ثانية. أما وضع stream فلا يرسل شيئاً ويأخذ أول بايتين يبثّهما الجهاز:

```bash
export EMBDIAG_UART_DEV=/dev/ttyUSB0 EMBDIAG_UART_BAUD=115200
./emb-bus-diag-v2 --bus uart -r 2 --profile ina219 -n 5
# وضع البث المستمر: EMBDIAG_UART_MODE=stream
```

السرعات المدعومة: 9600 و19200 و38400 و57600 و115200، بصيغة 8N1 بدون تحكم بالتدفق. لفتح المنفذ أضف مستخدمك لمجموعة dialout: sudo usermod -aG dialout \$USER ثم سجّل الدخول من جديد.

> **ملاحظة:** بروتوكول UART هنا مبسّط ومخصص لهذه الأداة؛ يجب أن يرد برنامج الجهاز على طلب السجل كما هو موصوف، أو أن يبث قيمه باستمرار في وضع stream.

**Modbus TCP:** المعرّف -a هو رقم الوحدة و-r عنوان سجل الاحتفاظ. العنوان الافتراضي 127.0.0.1:1502 ويمكن تغييره بـEMBDIAG_MODBUS_HOST وEMBDIAG_MODBUS_PORT. للتجربة بخادم محلي:

```bash
pip install -r requirements-dev.txt
python3 modbus_server.py & # السجل 0 = 0x5DC0 أي 12.0 فولت
./emb-bus-diag-v2 --bus modbus -a 1 -r 0 -n 3
```

## الخطوة 9: الاستخدام من Python

```bash
make lib
python3 control.py
```

ينشئ المثال سياق إحصاءات في مكتبة C ويغذّيه بخمس قراءات، وتُكتشف القراءة الشاذة 25.0 بدرجة Z تقارب 15. وللاستخدام في شيفرتك:

```python
import control

s = control.Stats()
for v in [10.5, 11.0, 12.5, 10.0, 25.0]:
    st = s.update(v)
    print(st.ema_val, st.z_score, st.trend_slope)
```

# 5. مرجع سريع

## خيارات سطر الأوامر

| **الخيار** | **المعنى**                                                  | **الافتراضي** |
|-----------------------------------|------------------------------------------------------------------------------------|--------------------------------------|
| --bus                             | mock أو i2c أو spi أو can أو uart أو modbus                 | mock          |
| -b \<id\>                         | رقم الناقل (يحدد /dev/i2c-N أو spidevN أو vcanN أو ttyUSBN) | 1             |
| -a \<addr\>                       | عنوان الجهاز أو خط CS أو معرّف CAN أو رقم وحدة Modbus        | 1             |
| -r \<reg\>                        | عنوان السجل (0 إلى 255)                                     | 0             |
| -n \<count\>                      | عدد العينات                                                 | 5             |
| -i \<ms\>                         | الفاصل بين العينات بالمللي ثانية                            | 200           |
| --profile                         | raw أو ina219 أو ads1115 أو tmp102                          | ina219        |
| --metric                          | voltage أو temp أو pressure (يتجاوز نوع الملف)              | حسب الملف     |
| --scale \<x\>                     | معامل القياس، يجب أن يكون أكبر من صفر                       | حسب الملف     |
| -o \<file\>                       | مسار تقرير JSON                                             | report.json   |
| -h                                | عرض المساعدة                                                | -             |

## رموز الخروج

| **الرمز** | **المعنى**                                         |
|----------------------------------|---------------------------------------------------------------------------|
| 0         | نجاح وكل القراءات سليمة أو تحذير                   |
| 1         | خطأ في الخيارات، أو فشل فتح الناقل، أو فشل القراءة |
| 2         | قراءة واحدة على الأقل بحالة CRITICAL أو ERROR      |

**مثال أتمتة:**

```bash
./emb-bus-diag-v2 --bus i2c -b 1 -a 0x40 -r 0x02 -n 5 -o /tmp/v.json
case $? in 0) echo "ok";; 2) echo "voltage out of range";; *) echo "read error";; esac
```

| **المتغير** | **الوظيفة**                                        |
|------------------------------------|---------------------------------------------------------------------------|
| EMBDIAG_MOCK_SEED                  | قيمة بذرة لجعل قراءات الوضع التجريبي قابلة للتكرار |

| EMBDIAG_UART_DEV / \_BAUD / \_MODE | مسار منفذ UART وسرعته ووضعه (poll أو stream)       |

# 6. حل المشاكل الشائعة

| **الرسالة أو العرَض**        | **الحل**                                                                                            |
|----------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------|
| Error: Init failed. مع i2c  | تأكد من تفعيل الناقل ووجود /dev/i2c-1، ومن العنوان بـ i2cdetect، ومن الصلاحيات (sudo أو مجموعة i2c) |
| cannot open /dev/ttyUSB1                           | الافتراضي ttyUSB\<b\>؛ استخدم -b 0 أو حدد EMBDIAG_UART_DEV، وتأكد من مجموعة dialout                 |
| HAL read failed مع uart     | لم يرد الجهاز خلال ثانية: راجع السرعة، وعكس خطّي TX وRX، ووضع poll أو stream                         |
| bus is not supported in this build                 | بُنيت الأداة بدون Modbus: ثبّت libmodbus-dev ثم نفّذ make clean && make                                |
| فشل Init مع can             | الواجهة غير مفعّلة: افحص ip link، وحدد EMBDIAG_CAN_IFACE إن لم تكن vcan                              |
| رمز الخروج 2 رغم عمل الجهاز | القيمة خارج العتبات: تأكد من --profile و--scale المناسبين لحساسك (الافتراضي ina219)                 |
| قيمة Z تبقى صفراً            | تحتاج 4 عينات سابقة على الأقل؛ استخدم -n 5 أو أكثر                                                  |
| libembdiag.so not found                            | نفّذ make lib قبل تشغيل Python                                                                       |

# 8. حدود المشروع (للأمانة)

- مشغّلات I2C وSPI وCAN بُنيت واختُبر فشلها النظيف عند غياب الجهاز، لكنها لم تُجرَّب على عتاد حقيقي أثناء التطوير؛ جرّبها على لوحتك وأبلغ عن أي فرق.

- اختُبر Modbus من البداية للنهاية على GitHub، واختُبر UART على منفذ افتراضي (pseudo-terminal).

- حساس BME280 غير مدعوم لأن قراءة الضغط تحتاج معاملات معايرة وتعويضاً غير منفّذ.

- العتبات (الجهد والحرارة والضغط) ثابتة داخل الكود، وتغييرها يتطلب تعديل src/diag.c وإعادة البناء.

- بروتوكول UART خاص بهذه الأداة (طلب بايت واحد ثم ردّ بايتين)، وليس بروتوكولاً قياسياً.

- معرّفات CAN المدعومة حتى 255 فقط.
